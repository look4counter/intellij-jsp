# 기능 명세: 선언부와 함수 포매팅 정렬

**작성일**: 2026-10-20
**상태**: 검증 완료
**입력**: page 지시자 뒤 `<%!` 선언부와 함수 및 `%>`의 들여쓰기가 서로 맞지 않는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 선언부 정렬 (우선순위 P1)

개발자는 전체 재정렬로 잘못 들여쓴 선언부와 함수를 일관된 위치로 복원한다. 선언부가 잘못 정렬되면 함수의 구조를 읽기 어려우므로 우선 수정한다.

독립 검증: 제공된 page·선언부·div 예시를 재정렬하고 다시 실행한다.

1. 최상위 `<%!`와 `%>`는 0열로 정렬한다.
2. 독립된 여러 줄 선언부의 함수는 선언부보다 한 단계, 함수 본문은 함수보다 한 단계 더 들여쓴다.
3. HTML 안에서는 선언부의 양쪽 구분자가 부모 HTML 들여쓰기를 따른다.

### 사용자 이야기 2 — 함수 스타일과 기존 편집 보존 (우선순위 P1)

개발자는 선언부에서도 설정한 Java 함수 스타일을 사용하며 선택하지 않은 코드는 보존한다.

독립 검증: 함수 인자·중첩 블록·Java 들여쓰기 설정과 부분 선택을 확인한다.

1. Java 공백·중괄호·들여쓰기 설정을 함수에 적용한다.
2. 문자열·주석·한글 내용과 선택 영역 밖의 텍스트를 보존한다.
3. 기존 한 줄 선언부·스크립틀릿·표현식·지시자와 HTML 포매팅은 계속 동작한다.

## 경계 사례

여러 선언부, 빈 선언부, 미완성 선언부, 여러 줄 문자열과 주석, 탭 설정 및 선언부 일부만 선택하는 경우를 고려한다. 원문 토큰은 변경하지 않는다.

## 요구사항

- **FR-001**: 최상위 선언부의 추가 연속 들여쓰기를 제거하고 HTML 내부 선언부는 부모 구조를 따른다.
- **FR-002**: 독립된 여러 줄 선언부는 시작·종료 구분자를 정렬하고 Java 멤버와 함수 본문을 상대 단계에 맞춰 정렬한다.
- **FR-003**: 함수의 인자·연산자·중괄호·중첩 블록과 들여쓰기에 기존 Java 코드 스타일을 적용한다.
- **FR-004**: 비공백 토큰·문자열·주석 내용과 선택 영역 밖을 보존하고 반복 재정렬 결과를 동일하게 유지한다.
- **FR-005**: 기존 Java·지시자·HTML·JS·CSS 편집 회귀 및 전체 테스트·배포 빌드·설정 검증을 통과한다.

## 성공 기준

- **SC-001**: 사용자 예시에서 시작·종료 구분자 0칸, 함수 4칸, return 8칸으로 정렬된다(기본 설정).
- **SC-002**: 사용자 지정 Java/HTML 들여쓰기와 반복 실행·부분 선택·본문 보존 검증이 통과한다.
- **SC-003**: 전체 자동 검증과 배포 빌드가 성공한다.

## 가정과 명확화 검토

speckit-clarify에서 범위·편집 동작·보존 조건·완료 기준을 검토했다. 여러 줄 선언부는 기존 Java 들여쓰기 한 단계를 적용하고 구분자는 HTML 위치를 따른다. 한 줄 선언부를 강제로 여러 줄로 바꾸지 않으며 Enter 동작은 범위 밖이다. 중요한 모호성이 없어 질문은 없다.
