# 연구: 선언부 정렬

## 원인과 결정

- 결정: 선언부 JAVA_HOST와 DECLARATION 잎에도 명시적 들여쓰기 정책을 적용한다.
- 근거: 현재 포매터는 DIRECTIVE_HOST만 처리하므로 선언부는 기본 연속 들여쓰기 8칸을 받는다.
- 대안: 문서의 선행 공백을 정규식으로 지우는 방법은 HTML 구조와 선택 범위를 훼손하므로 제외했다.

## 함수 본문 투영

- 결정: 전체가 선택된 독립 여러 줄 선언부는 HTML 정렬 후 확정된 위치에 Java 포매팅을 투영한다.
- 근거: 기존 전처리는 trim한 코드만 교체해서 첫 코드 앞 12칸과 종료 구분자 앞 16칸을 남긴다. 내부 줄에서는 가상 클래스의 들여쓰기를 제거하므로 함수와 본문 위치가 어긋난다.
- 대안: 기존 전처리에서 현재 호스트 들여쓰기만 기준으로 삼으면 후속 HTML 정렬이 바꾸는 위치를 반영하지 못한다. 모든 Java를 후처리로 옮기는 방법은 부분 선택과 스크립틀릿 범위를 넓히므로 제외했다.

speckit-plan 연구 에이전트가 기존 주입·포매팅·테스트 경로와 후처리 API를 읽기 전용으로 조사했다.

## 선택 범위와 원문 보존 보완

- SDK의 후처리 범위는 선택 위치를 담은 PSI 전체 범위로 확대될 수 있다. 전처리에서 전체 선택된 선언부의 문서 범위 마커를 저장하고 후처리에서 허용 목록으로 소비·해제한다. 여러 전처리 범위는 병합한다.
- Java 포매터는 주석과 여러 줄 문자열의 내부 공백도 바꿀 수 있다. Java 렉서로 원본 토큰을 보존하고 포매터가 계산한 토큰 사이 공백만 투영한다. 가상 들여쓰기 제거와 실제 들여쓰기 추가 역시 WHITE_SPACE 토큰에만 적용한다.
- 실제 HTML 태그가 전혀 없는 파일은 바깥 선행 공백을 유지할 수 있다. HTML PSI에 태그가 없고 원래 선택 범위가 해당 공백을 포함한 경우에만 최상위 선행 공백을 제거한다. HTML 태그가 있으면 기존 HTML 포매터의 위치를 따른다.
- 선행 공백 삭제는 후처리 범위의 시작 위치도 이동시킬 수 있으므로 반환 범위를 문서 범위 마커로 추적한다.
