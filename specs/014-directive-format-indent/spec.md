# 기능 명세: 연속 지시자 포매팅 들여쓰기 수정

**작성일**: 2026-10-20
**상태**: 명세 검증 완료
**입력**: 재정렬하면 첫 page import 다음의 page·include 지시자에 공백 8칸이 붙는다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 최상위 지시자 정렬 (우선순위 P1)

개발자는 연속된 최상위 JSP 지시자를 재정렬해도 같은 열에 정렬된 결과를 얻는다.
독립 검증: 사용자 예시와 이미 8칸 들여쓴 예시를 재정렬하고 반복 실행 결과를 확인한다.

1. 최상위 page import·page contentType/pageEncoding·include와 뒤의 doctype을 0열에 유지한다.
2. 이미 잘못 들여쓴 지시자는 최상위 정렬로 복원한다.
3. 작은따옴표·빈 줄·JSP 주석·여러 줄 지시자에서도 내부 원문을 보존한다.

### 사용자 이야기 2 — 기존 포매팅 보존 (우선순위 P1)

개발자는 HTML 내부의 들여쓰기와 Java·JS·CSS·선택 영역 재정렬을 계속 사용한다.
독립 검증: HTML 내부 지시자·일반 HTML·선택 영역·기존 전체 포매팅 회귀를 확인한다.

## 요구사항

- **FR-001**: 연속된 최상위 page·include·taglib 지시자의 재정렬에서 불필요한 8칸 들여쓰기를 넣지 않는다.
- **FR-002**: 기존 잘못된 선행 들여쓰기를 복원하고 반복 재정렬 결과를 동일하게 유지한다.
- **FR-003**: 지시자 내부 속성·따옴표·여러 줄·한글과 주변 doctype·빈 줄·주석의 내용을 보존한다.
- **FR-004**: HTML 내부 지시자는 해당 HTML 구조의 들여쓰기를 따르며 다른 언어·선택 영역·Enter·이동·완성 기능을 보존한다.
- **FR-005**: 기존 및 신규 자동 검증·배포 빌드·설정 검증을 통과한다.

## 성공 기준

- **SC-001**: 사용자 예시의 세 최상위 지시자와 doctype이 모두 0열에 있다.
- **SC-002**: 반복 재정렬·원문 보존·HTML 내부·선택 영역 회귀가 통과한다.
- **SC-003**: 전체 테스트와 배포 빌드가 성공한다.

## 가정과 범위

Enter 처리와 별개인 재정렬 경로를 수정한다. 지시자 의미나 내부 원문을 바꾸지 않으며 전체 문서의 일반적인 HTML 포매팅은 유지한다. 태그·코드 스타일을 새로 정의하지 않는다.

## 명확화 검토

speckit-clarify로 제공된 재현 코드·기대 정렬·본문 보존·선택 범위·의존성과 완료 기준을 검토했다. 최상위 형제 지시자는 0열이라는 기본값으로 확정했으며 추가 질문은 없다.
