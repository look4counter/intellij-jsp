# 기능 명세: JSP Java import 자동 추가

**작성일**: 2026-10-20
**상태**: 명세 검증 완료
**입력**: Java Import 자동추가가 되도록 만들어줘

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 클래스 완성과 import 추가 (우선순위 P1)

개발자는 JSP Java 영역에서 프로젝트 클래스를 완성하면 필요한 page import를 함께 추가한다.
우선 이유: 지시자 수동 작성을 줄인다. 독립 검증: 완성 선택 후 원문과 클래스 해석을 확인한다.

1. 스크립틀릿·표현식·선언에서 클래스를 선택하면 현재 파일에 import를 추가한다.
2. 이미 유효한 명시적·와일드카드·include import 및 java.lang 타입은 중복 추가하지 않는다.
3. 같은 단순 이름의 다른 타입과 충돌하면 기존 해석을 바꾸지 않고 선택 타입을 완전한 이름으로 사용한다.

### 사용자 이야기 2 — 미해결 클래스 빠른 수정 (우선순위 P1)

개발자는 미해결 클래스에서 Alt+Enter로 원하는 클래스를 골라 import를 추가한다.
우선 이유: 기존 코드를 다시 입력할 필요가 없다. 독립 검증: 빠른 수정 선택 후 원문과 해석을 확인한다.

1. 접근 가능한 프로젝트 클래스 후보를 제공하고 선택 타입만 추가한다.
2. 동명 클래스는 패키지를 구분하여 사용자가 선택한다.
3. HTML·주석·문자열·EL에서는 import 수정을 제공하지 않는다.

### 경계 사례

- 기존 지시자·따옴표·여러 import·줄바꿈·한글을 보존한다.
- include 조각에서는 현재 파일만 변경하며 여러 부모 정책을 유지한다.
- 읽기 전용·인덱싱·후보 없음에서는 부적절한 쓰기를 하지 않는다.
- 실행 취소로 import와 완성 또는 수정을 되돌린다.

## 요구사항

- **FR-001**: Java 클래스 완성 선택 시 필요한 JSP page import를 자동 추가한다.
- **FR-002**: 미해결 클래스에 Alt+Enter import 후보를 제공한다.
- **FR-003**: 유효한 기존 import를 재사용하고 중복을 방지한다.
- **FR-004**: 타입 이름 충돌 시 기존 참조 의미를 보존한다.
- **FR-005**: 현재 JSP·JSPF만 변경하고 주변 원문·커서·실행 취소를 보존한다.
- **FR-006**: 세 Java 영역에서 동작하고 다른 언어·주석·문자열에는 적용하지 않는다.
- **FR-007**: 기존 편집·include·이동과 빌드 검증을 통과한다.

### 주요 개체

- import 후보: 클래스 단순 이름·완전한 이름·접근 가능 여부.
- import 문맥: 번역 단위의 명시적·와일드카드 import.
- 편집 결과: 현재 파일에 추가한 지시자와 참조 표기.

## 성공 기준

- **SC-001**: 세 Java 영역에서 완성 후 지시자를 직접 작성하지 않고 선택 타입을 사용한다.
- **SC-002**: 빠른 수정과 복수 후보 선택 시 원하는 클래스만 가져온다.
- **SC-003**: 중복·충돌·include·비대상 위치 검증에서 잘못된 import와 원문 손상이 없다.
- **SC-004**: 기존 및 신규 자동 검증과 배포물 빌드가 통과한다.

## 가정과 범위

프로젝트에 등록한 클래스와 라이브러리를 사용한다. 사용자 선택을 기준으로 추가하며 입력만으로 임의의 후보를 선택하지 않는다. 기존 지시자를 재작성하지 않고 별도 page import 지시자를 추가할 수 있다. 정적 import, import 정리·삭제, EL·태그 클래스 추론은 제외한다.
