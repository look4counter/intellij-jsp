# 연구: 자바 편집 엔진 재사용

- 결정: `MultiHostInjector`와 복합 `PsiLanguageInjectionHost`를 사용한다. 공식 SDK의 가상 클래스·메서드 예제를 따른다.
- 이유: 원문 위치 매핑, Java PSI 및 코드 완성을 플랫폼에 위임할 수 있다.
- 대안: Java FileViewProvider는 길이가 달라지는 가상 코드 위치 대응을 별도로 구현해야 한다. 독자 완성 엔진은 재사용 목적과 맞지 않는다.
- 문맥: page import와 표준 JSP import, 내장 객체, 클래스 선언 및 실행 메서드 순으로 연결한다. 원문 뒤의 선언을 앞쪽 주입 조각으로 재배열하면 편집 위치 매핑이 불안정하므로 선언과 실행을 별도 주입으로 구성한다. 실행 주입의 클래스 본문에 선언 사본을 제공한다. 선언 참조 탐색은 가상 사본을 가리킬 수 있으며 이번 범위인 완성·강조·포매팅은 원문 순서의 호스트를 사용한다.
- 서블릿: 프로젝트의 jakarta를 우선하고 없으면 javax를 사용한다. 라이브러리가 없으면 미해결 타입을 허용한다.
- 편집: 원문 escaper로 백슬래시와 한글을 그대로 대응하고 updateText로 호스트를 교체한다.
- 포매팅: 표준 주입만으로 기존 JSP 모델은 자바 내부를 재정렬하지 않았다. 주입 문서를 직접 재정렬하면 분리된 조각에서 위치와 선택 범위가 손상되는 사례가 확인되어, Java 사본의 범위 마커로 결과를 추적하고 선택한 JSP 본문에만 반영한다. HTML 포매팅 전 원래 선택 범위로 처리하여 후처리의 범위 확대를 피한다. 가상 클래스 공백과 접두·접미 코드는 반영하지 않는다.
- 강조: 주입의 의미 강조에 더해 기존 Java 렉서 계층으로 키워드·문자열·주석의 즉시 강조를 제공한다. 같은 종류 조각을 연결하는 계층 문서에서도 각 JSP 구분자에서 렉서 문맥을 새로 시작한다.
- 들여쓰기: Java 사본의 클래스·메서드에서 유래하는 기본 들여쓰기를 반영 결과에서 제거한다. Java 렉서의 공백 토큰만 조정하여 문자열과 주석 내부의 문자를 보존한다.
- 근거: [공식 언어 주입 문서](https://plugins.jetbrains.com/docs/intellij/language-injection.html).
