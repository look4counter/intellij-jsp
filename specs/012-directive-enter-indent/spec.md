# 기능 명세: 지시자 뒤 Enter 들여쓰기 수정

**작성일**: 2026-10-20
**입력**: page import·page contentType/pageEncoding·include 지시자의 `%>` 뒤 Enter에서 다음 줄에 공백 8칸이 붙는다.
**상태**: 명세 검증 완료

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 지시자 다음 줄 정렬 (우선순위 P1)

개발자는 독립된 줄의 JSP 지시자 종료 직후 Enter를 누르면 불필요한 추가 들여쓰기 없이 다음 줄을 작성한다.
독립 검증: 사용자 제공 세 지시자의 종료 뒤 실제 Enter 동작을 실행한다.

1. 최상위 page·include 지시자 뒤 다음 줄은 공백 8칸 없이 시작한다.
2. 기존 줄에 선행 공백·탭이 있으면 같은 들여쓰기를 유지한다.
3. 반복 Enter와 파일 끝·다음 지시자 앞에서도 원문과 커서가 올바르다.

### 사용자 이야기 2 — 다른 편집 동작 보존 (우선순위 P1)

개발자는 Java 본문과 HTML 안에서는 기존 Enter·포매팅 동작을 유지한다.
독립 검증: 일반 HTML·Java 본문·미완성 지시자·다른 파일 유형의 Enter와 기존 회귀를 확인한다.

## 요구사항

- **FR-001**: JSP·JSPF의 독립된 줄에 있는 닫힌 page·include·taglib 지시자 직후 Enter에서 기존 줄 들여쓰기를 보존하고 추가 8칸을 넣지 않는다.
- **FR-002**: 선행 공백·탭·종료 뒤 공백·반복 Enter·파일 끝과 다음 지시자 앞에서 본문과 커서를 보존한다.
- **FR-003**: Java 본문·일반 HTML·인라인 지시자·미완성 지시자·다른 파일 유형은 기존 처리에 맡긴다.
- **FR-004**: 한 번의 실행 취소로 Enter를 복원하며 기존 완성·import·이동·include·포매팅과 빌드 검증을 통과한다.

## 성공 기준

- **SC-001**: 사용자 예시의 세 줄 모두에서 Enter 후 의도하지 않은 선행 공백이 0칸이다.
- **SC-002**: 들여쓰기·커서·실행 취소·비대상 검증과 전체 회귀 및 배포 빌드가 통과한다.

## 가정과 범위

닫힌 지시자가 줄에서 독립적으로 시작하고 커서가 종료 뒤에 있는 경우를 수정한다. 여러 줄 지시자는 시작 줄의 들여쓰기를 사용한다. 일반 코드 재정렬과 지시자 내부 Enter 정책은 변경하지 않는다.

## 명확화 검토

speckit-clarify로 제공한 재현 코드와 원문 보존·경계·의존성을 검토했다. 지시자 뒤에서 추가된 들여쓰기를 제거하는 범위이며 추가 질문은 없다.
