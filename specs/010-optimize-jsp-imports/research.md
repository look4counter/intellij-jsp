# 연구: JSP import 정리

## 현재 결정: 기능 철회

사용자 요청으로 정리 액션·Ctrl+O 연결·우선순위 제공자·분석기·전용 테스트를 제거한다. 참조 검색 결과 include의 완전성·방문 파일 정보도 정리에서만 사용하므로 함께 복원한다. 아래 추가 설계는 폐기된 이력이다.

- 결정: JavaCodeStyleManager.findRedundantImports로 미사용 여부를 분석한다. 근거: 로컬 261 SDK API와 연구 에이전트의 바이트코드 확인. 단순 문자열 검색은 주석·문자열·완전한 클래스 이름을 오판하므로 채택하지 않는다.
- 결정: 모든 주입 Java 파일의 판정을 교차 확인한다. 근거: 선언과 스크립틀릿·표현식은 별도 주입 파일이며 include 코드도 가상 영역에 포함된다.
- 결정: 분석기로 제거 목록만 계산하고 JSP 원문을 편집한다. Java 정리 실행은 편집 불가 가상 import를 수정하므로 사용하지 않는다.
- 결정: 전용 액션은 최상위 JSP를 찾고 Ctrl+O 충돌 시 ActionPromoter로 우선한다. 로컬 기본 키맵에서 Ctrl+O는 OverrideMethods다. 일반 Java 파일에서는 비활성화한다.
- 결정: include 완전성 플래그를 제공해 불완전 문맥에서는 제거를 생략한다. 모호한 부모에서 현재 파일만 사용하는 기존 정책은 읽기용이며 삭제 판정에는 충분하지 않다.
- 결정: 원문 범위로 import 속성을 갱신한다. 다른 속성과 지시자 주변 공백·줄바꿈을 보존한다.
