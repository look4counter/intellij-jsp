# 검증 안내

page·include·taglib의 구분자·이름·속성·등호·문자열을 확인한다. 미완성 문자열과 여러 지시자를 편집하고 테마를 바꿔 색상 역할이 유지되는지 확인한다. Ctrl+Space와 구분 문자로 이름·속성·import 클래스·include 경로를 완성하고 목록·따옴표·커서가 보존되는지 확인한다.

기존 [로컬 SDK 명령](../009-java-auto-import/quickstart.md)의 test buildPlugin verifyPluginProjectConfiguration으로 전체 회귀를 실행하고 결과를 기록한다.

## 검증 결과

2026-10-20, IntelliJ IDEA 2026.1.3 SDK에서 전체 테스트 134개가 통과했다. 신규 테스트는 색상 4개·완성 13개이며 실패·오류는 0개다. buildPlugin과 verifyPluginProjectConfiguration이 성공했다.

- 구분자·지시자 이름·속성·등호·문자열의 서로 다른 색상 키, 여러 줄·미완성 문자열과 다음 지시자의 독립성, 증분 편집과 사용 가능한 테마를 확인했다.
- 실제 완성 선택으로 단순·완전한 클래스 이름, 목록 중간 항목·기존 접미사·따옴표·커서, 패키지·중첩 클래스·소스 없는 의존 JAR 클래스를 확인했다.
- include 파일·폴더·경로 마지막 요소·상대·상위·웹 루트 경로와 없는 디렉터리를 확인했다.
- 접근 불가 클래스 제외, 인덱싱 중 클래스 검색 생략·고정값 유지, 기존 속성·대표 값 및 비대상 문맥 회귀를 확인했다.
- 실제 등록 typedHandler의 구분 문자 팝업 예약 계약과 JSP 주석·HTML·종료 뒤의 비대상 처리를 확인했다.
- 점으로 패키지·슬래시로 폴더를 선택할 때 구분 문자가 중복되지 않는다. 수정 전 패키지 점 중복을 재현하고 수정 후 통과했다.
- 기존 HTML·Java·JS·CSS 강조·완성·Enter·import 자동 추가·선언 이동·include·포매팅 회귀가 통과했다.
- ZIP 내부 강조 레이어·완성 기여자·입력 처리기 및 typedHandler 등록을 확인했으며 테스트 클래스는 포함되지 않는다.

## 환경과 수렴 점검

기존 로컬 호환 테스트 도구와 읽기 전용 의존성 캐시를 사용하고 검증에서만 계측을 껐다. 제품 코드와 언어 엔진은 실제 261 SDK다. IDE 화면의 색상 육안 확인·팝업 직접 조작과 정식 261 테스트 프레임워크 재검증은 수행하지 않았다. 실제 표시 색상은 사용 중인 테마의 기본 역할을 따른다.

speckit-converge에서 구형 팝업 훅의 호출 경로를 T008로, 구분 문자 선택의 중복을 T009로 보완했다. 재점검 결과 FR-001~008·두 사용자 이야기·편집 계약·T001~T009에 남은 구현 차이는 없다. 헌장은 미작성 템플릿으로 원칙 검사를 생략했다.

설치 파일: `build/distributions/intellij-jsp-1.0.0-SNAPSHOT.zip`. 설치 후 IDE를 재시작한다.
