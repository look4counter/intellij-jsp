# 기능 명세: JSP 정적 include 문맥 연결

**작성일**: 2026-10-20
**상태**: 검토 완료
**입력**: include 파일 사이의 문맥 연결을 구현한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — 포함된 코드 사용 (우선순위: P1)

개발자는 정적 include로 포함한 파일의 import·선언·실행 코드를 같은 페이지의 일부로 사용한다.
우선 이유: 공통 JSP 조각의 변수와 메서드 완성이 핵심 목적이다.
독립 검증: 포함 파일의 변수와 메서드, import된 클래스 멤버를 본문에서 완성한다.

1. 포함된 선언과 import는 전체 페이지에서 사용한다.
2. 지역 변수는 include 삽입 순서와 중괄호 범위에 따라 보인다. 뒤에서 선언된 변수는 앞에서 보이지 않는다.
3. 여러 단계의 상대경로 include와 웹 루트 기준 경로를 처리한다.
4. include.jsp의 test 메서드는 반환값이 있는 표현식 및 void 호출이 가능한 스크립틀릿 위치에서 Java 완성 후보로 제공한다. 기본 완성과 스마트 완성의 후보 필터링, 문맥 연결 실패를 구분한다.

### 사용자 이야기 2 — 조각 파일 편집 (우선순위: P1)

개발자는 부모 페이지가 하나인 JSP 조각을 열어 부모가 제공하는 문맥으로 편집한다.
우선 이유: include 안의 코드에도 같은 완성 기능이 필요하다.
독립 검증: 부모의 앞선 변수와 import를 조각의 완성에 사용한다.

1. 포함 경로가 하나로 정해지면 최상위 부모 페이지의 문맥을 사용한다.
2. 여러 부모나 같은 조각의 여러 삽입 위치가 있으면 조각 자체의 문맥만 사용한다.
3. jspf 파일도 JSP 편집 기능을 사용한다.

### 사용자 이야기 3 — 변경 반영과 편집 보존 (우선순위: P2)

개발자는 포함 파일을 수정·생성·삭제한 뒤 새 문맥으로 완성하며, 현재 파일의 편집과 재정렬은 다른 파일을 변경하지 않는다.
독립 검증: 파일 및 지시자 변경 뒤 재주입 결과와 문서 내용을 비교한다.

1. 커밋된 미저장 편집과 파일 생성·삭제를 다음 문맥 계산에 반영한다.
2. 완성 선택과 재정렬은 현재 JSP만 변경한다.
3. 순환·누락·미완성 경로에서도 편집을 계속할 수 있다.

### 경계 사례

- 반복 include는 원래 삽입 순서를 유지한다. 무한 순환은 현재 경로에서 중단한다.
- 상대경로는 지시자가 들어 있는 파일 기준이다.
- 인덱싱 중에는 역방향 부모 탐색을 생략하고 현재 파일의 직접 include 문맥을 유지한다.
- JSP 주석에 들어 있는 include와 동적 jsp:include는 Java 문맥을 합치지 않는다.

## 요구사항

- **FR-001**: 정적 include의 import와 선언을 공유하고 실행 코드는 삽입 순서대로 연결해야 한다.
- **FR-002**: 중첩 상대경로와 웹 루트 기준 경로를 해석해야 한다.
- **FR-003**: 조각의 유일한 부모 문맥을 연결하고 여러 부모·여러 삽입 위치는 자체 문맥으로 처리해야 한다.
- **FR-004**: jspf 파일을 JSP 파일 유형으로 편집할 수 있어야 한다.
- **FR-005**: 포함 파일 편집, 경로 변경 및 파일 생성·삭제를 반영해야 한다.
- **FR-006**: 순환·누락·미완성·과도한 중첩을 안전하게 처리하고 동적 include와 주석은 구분해야 한다.
- **FR-007**: 완성 및 포매팅은 현재 파일에만 반영하고 기존 편집 기능을 유지해야 한다.
- **FR-008**: 실제 HTML 페이지와 include.jsp의 test 메서드를 사용해 반환형·호출 위치별 완성을 재현하고 정상 Java 위치의 완성 누락이 있으면 수정해야 한다.

### 주요 개체

- 포함 관계: 부모, 지시자 위치, 정적 경로와 대상 파일.
- 페이지 문맥: 삽입 순서의 자바 조각, 전체 import 및 선언.
- 편집 대상: 실제 수정 가능한 현재 파일의 자바 영역.

## 성공 기준

- **SC-001**: 포함 방향과 유일 부모 방향의 실제 완성 및 범위 검증이 통과한다.
- **SC-002**: 중첩·다중 부모·순환·동적 include 제외 및 변경 반영 검증이 통과한다.
- **SC-003**: 현재 파일 완성과 포매팅에서 다른 파일의 원문이 보존된다.
- **SC-004**: 기존 테스트와 빌드·설정 검증에 실패가 없다.

## 가정과 범위

정적 include 지시자를 대상으로 한다. XML 문법 JSP, web.xml의 prelude/coda, EL·태그 라이브러리 문맥, include 경로 자동완성과 선언 탐색 개선은 범위 밖이다. 웹 루트는 현재 콘텐츠 루트 안의 가장 가까운 webapp·WebContent·web 디렉터리 또는 WEB-INF를 가진 상위 디렉터리이며, 없으면 콘텐츠 루트를 사용한다. 모호한 웹 루트를 임의로 다른 모듈에서 찾지 않는다.

## 명확화

### 2026-10-20

- 질문: 같은 조각을 여러 부모가 포함할 때 어떤 문맥을 사용하는가? → 답변: 여러 부모가 있으면 조각 자체 문맥만 사용한다.
- 후속 버그 검토: 사용자가 test 메서드 완성 누락을 보고했다. 제공된 선언은 public void test()이고 사용 위치는 출력 표현식이다. 같은 이름의 반환값 메서드와 스크립틀릿 호출을 함께 재현하여 Java 후보 필터링과 주입 문제를 구분한다.
- 후속 답변: 반환값이 있는 함수도 완성되지 않는다. void 반환형만으로 원인을 단정하지 않고 실제 HTML 문맥과 포함 파일 로드를 검증한다.
- 실제 원인 확인: 예제 프로젝트의 지시자는 ./include.jsp를 참조하지만 파일명은 incldue.jsp다. 경로가 일치하는 반환값 메서드 완성과 void 스크립틀릿 완성은 재현 테스트에서 정상 동작했다.
