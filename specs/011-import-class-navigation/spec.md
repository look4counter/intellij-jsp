# 기능 명세: import 클래스 선언 이동

**작성일**: 2026-10-20
**상태**: 명세 검증 완료
**입력**: import 구문에서 Ctrl+클릭으로 해당 클래스로 이동한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — import 클래스 이동 (우선순위 P1)

개발자는 JSP·JSPF의 page import에 적힌 클래스 이름을 Ctrl+클릭하거나 Ctrl+B로 선언을 연다.
우선 이유: import한 클래스의 구현을 바로 확인한다.
독립 검증: 프로젝트 클래스의 import에서 선언 이동을 실행해 대상 클래스를 확인한다.

1. 단일 import의 클래스 이름에서 해당 클래스 선언으로 이동한다.
2. 쉼표로 구분한 각 항목과 여러 page 지시자에서 선택한 클래스만 연다.
3. 작은따옴표·큰따옴표·공백·줄바꿈이 있어도 정확한 이름 범위에서 동작한다.
4. 프로젝트 해석 범위에 등록된 라이브러리와 중첩 클래스도 기존 Java 탐색 정책으로 연다.

### 사용자 이야기 2 — 비대상과 기존 탐색 보존 (우선순위 P1)

개발자는 다른 텍스트나 잘못된 import에서 엉뚱한 클래스로 이동하지 않기를 기대한다.
독립 검증: 와일드카드·없는 클래스·쉼표·주석·다른 속성에서 잘못된 대상을 제공하지 않는지 확인한다.

1. 와일드카드·미해결·잘못된 클래스 이름에는 임의의 클래스 대상을 제공하지 않는다.
2. 클래스 이름 바깥의 쉼표·공백·따옴표·속성 이름과 JSP 주석은 링크가 아니다.
3. 기존 include 경로·Java 함수 이동과 자동 import 동작을 보존한다.

## 요구사항

- **FR-001**: JSP·JSPF page import의 명시적 클래스에 Ctrl+클릭 및 선언 이동을 제공한다.
- **FR-002**: 목록의 각 클래스 이름을 정확한 원문 범위로 구분하고 따옴표·공백·줄바꿈·여러 지시자를 지원한다.
- **FR-003**: 프로젝트 해석 범위의 소스·라이브러리·중첩 클래스를 기존 Java 탐색 정책으로 해석한다.
- **FR-004**: 와일드카드·미해결·문법 오류·비대상 위치·인덱싱 중 잘못된 대상을 반환하지 않는다.
- **FR-005**: 탐색으로 문서를 수정하지 않으며 include·Java 이동·자동 import·기존 편집 기능의 회귀 검증과 빌드를 통과한다.

### 주요 개체

- import 참조: 클래스의 완전한 이름과 지시자 안의 원문 범위.
- 이동 대상: 현재 프로젝트에서 해석 가능한 클래스 선언과 플랫폼 탐색 대상.

## 성공 기준

- **SC-001**: 단일·복수 import의 각 이름에서 한 번의 선언 이동으로 정확한 클래스를 연다.
- **SC-002**: 비대상·미해결 검증에서 잘못된 클래스 이동과 문서 변경이 0건이다.
- **SC-003**: 신규 및 기존 자동 검증과 플러그인 배포 빌드가 통과한다.

## 가정과 범위

대상은 JSP·JSPF의 page import이며 일반 Java의 import 탐색은 기존 IDE가 처리한다. 와일드카드의 패키지 이동, 정적 import, import 이름 변경과 자동 정리는 제외한다. 클래스 소스가 없으면 라이브러리의 기존 탐색·디컴파일 동작을 따른다.
