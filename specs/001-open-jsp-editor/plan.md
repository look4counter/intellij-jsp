# 구현 계획: JSP 파일 열기

**작성일**: 2026-10-19 | **명세**: [spec.md](spec.md)
**브랜치**: 없음. 스크립트의 기능명은 디렉터리 식별자이다.

## 요약

JSP 텍스트 파일 유형을 등록하고 기본 에디터의 열기·편집·저장을 재사용한다. 사용하지 않는 LSP 의존성을 플랫폼 모듈로 바꾼다.

## 기술 환경

- Kotlin 2.3.20, Gradle 9.7.1, IntelliJ IDEA 2025.3.6.1의 무료 기능 환경을 대상으로 한다.
- 저장과 인코딩은 IDE에 위임한다. 외부 서비스와 추가 저장소는 없다.
- 검증은 Gradle 빌드와 플러그인 구성 검사 및 수동 수용 시나리오로 진행한다.
- 범위는 `.jsp` 유형 하나이며 파싱과 언어 서버는 포함하지 않는다.

## 원칙 점검

헌법은 미작성 템플릿이므로 구체 원칙 검사를 생략한다. AGENTS.md의 한글 문서와 speckit 순서를 적용한다. 설계 전후 위반 없음.

## 조사와 설계

[조사](research.md)에 따라 비바이너리 FileType을 직접 구현한다. 별도 에디터 제공자는 필요 없다. 등록 이름은 내장 유형과 구분되는 Community JSP, 설명은 JSP이다. 확장자만 선언적으로 연결하며 사용자 설정을 강제 변경하지 않는다.

## 프로젝트 구조

- `src/main/kotlin/com/look4counter/jsp/JspFileType.kt`: 텍스트 파일 유형 싱글턴.
- `src/main/resources/META-INF/plugin.xml`: 파일 유형 등록과 기본 플랫폼 의존성.
- `README.md`: 한글 기능 설명, 빌드 및 설치 안내.
- `specs/001-open-jsp-editor/`: 명세, 계획, 조사, 데이터 모델, 계약, 검증 안내, 작업 목록.

## 단계

1. 환경과 의존성을 확인한다.
2. 파일 유형과 확장점 등록을 구현한다.
3. 빌드와 구성 검사를 수행하고 검증 방법을 문서화한다.
4. 명세와 구현의 차이를 점검한다.

## 복잡도

별도 에디터, 파서, 저장 로직 없이 기본 플랫폼을 사용한다.
