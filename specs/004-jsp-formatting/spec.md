# 기능 명세: JSP 웹 코드 포매팅

**작성일**: 2026-10-19
**상태**: 명세 검증 완료
**입력**: 기존 HTML·JavaScript·CSS 포매터를 재사용하여 JSP 코드 재정렬을 지원한다.

## 사용자 시나리오와 검증

### 사용자 이야기 1 — JSP 코드 재정렬 (우선순위: P1)

개발자는 JSP 편집기에서 코드 재정렬을 실행하여 HTML 들여쓰기와 사용 가능한 JavaScript·CSS 포매팅을 적용한다. 매번 별도 도구로 복사할 필요가 없으므로 가장 우선한다.

**독립 검증**: JSP 문서를 재정렬하고 같은 웹 코드를 담은 HTML 문서의 재정렬 결과와 비교한다.

1. HTML 태그가 중첩된 문서를 재정렬하면 기존 HTML 코드 스타일에 따라 정렬된다.
2. 스크립트와 스타일이 포함된 문서를 재정렬하면 사용 가능한 해당 언어 포매터가 적용된다.
3. 선택 영역만 재정렬하면 영역 밖의 코드는 유지된다.

### 사용자 이야기 2 — 서버 구문 보존 (우선순위: P1)

개발자는 JSP 지시자·주석·스크립틀릿·표현식·선언 및 EL이 섞인 파일도 안전하게 정렬한다.

**독립 검증**: 재정렬 전후 서버 구문 문자열을 비교하고 재실행 결과가 같은지 확인한다.

1. 모든 서버 구문의 내부 텍스트는 공백과 줄바꿈을 포함하여 동일하다.
2. 태그 속성, 텍스트, 스크립트와 스타일 내부의 서버 구문이 유실되거나 이동하지 않는다.
3. 빈 파일과 미완성 서버 구문에서도 예외나 내용 유실이 없다.

### 경계 조건

- 웹 언어 지원이 없는 환경에서도 HTML 정렬이 가능하다.
- 공백이 의미 있는 HTML 텍스트와 pre 영역은 기존 HTML 포매터의 정책을 따른다.
- 서버 구문 내부 Java와 EL 자체의 포매팅은 범위에서 제외한다.

## 요구사항

- **FR-001**: IntelliJ IDEA 2026.1에서 표준 코드 재정렬 동작으로 JSP를 포매팅해야 한다.
- **FR-002**: HTML 및 사용 가능한 JavaScript·CSS 포매터와 코드 스타일 설정을 재사용해야 한다.
- **FR-003**: JSP와 EL 토큰 내부의 원문을 보존해야 한다.
- **FR-004**: 전체 파일 및 선택 영역 재정렬을 지원해야 한다.
- **FR-005**: 빈 파일·미완성 구문·웹 언어 지원 부재에서도 내용 유실과 예외가 없어야 한다.
- **FR-006**: 기존 파일 열기·구문 강조·자동완성을 유지해야 한다.

## 성공 기준

- **SC-001**: HTML·JS·CSS 각각의 대표 예제에서 기존 에디터와 같은 정렬 결과를 얻는다.
- **SC-002**: 모든 서버 구문 종류의 보존 사례에서 내부 문자열 일치율이 100%이다.
- **SC-003**: 대표 문서를 두 번 재정렬한 결과가 동일하다.
- **SC-004**: 자동화된 포매팅 검증과 기존 회귀 검증이 모두 통과한다.

## 가정과 의존성

- 직전 제안을 승인한 것으로 해석하여 웹 코드 포매팅을 우선 구현한다.

- 외부 서비스와 영속 데이터는 추가하지 않는다.
